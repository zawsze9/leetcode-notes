# 98. Validate Binary Search Tree

**模式标签**：BST 区间约束（上下界递归）

**状态**：AC且最优

**完成方式**：纠错后通过

- **难度**：Medium
- **标签**：树、深度优先搜索、二叉搜索树
- **链接**：https://leetcode.cn/problems/validate-binary-search-tree/

## 题目描述

判断给定二叉树是否为**合法二叉搜索树（BST）**：每个节点的左子树只包含**严格小于**该节点的数，右子树只包含**严格大于**该节点的数，且左右子树也必须是 BST。

## 关键思路

核心洞察：**每个节点受的约束不是来自父亲，而是来自所有祖先**。沿路径向左走一步，上界收紧为当前节点值；向右走一步，下界收紧为当前节点值。于是每个节点实际受一个开区间 `(lo, hi)` 约束，根的区间是 `(-inf, +inf)`。

递归三段式：

1. 基线：`node` 为空 → 空子树合法，`return True`
2. 越界：不满足严格 `lo < node.val < hi` → `return False`
3. 合并：`return 左递归 and 右递归`（`and` 链自带短路，左边违规就不再递归右边）

配套套路：入口签名定死 → 递归主体搬进辅助函数 `dfs(node, lo, hi)`，入口只做"初始化 + 转发"。"入口签名定死 ≠ 所有函数签名定死"——#543 的嵌套函数 `dfs(node)` 已是同款。

等价路线：BST 的**中序遍历必须严格递增**，复用 #94 的中序框架，用 `self.prev` 记前驱（状态挂 self，即 #543 的 `self.diameter` 思路）。

## 代码实现

### 你的 AC 解法（区间约束版）

```python
class Solution:
    def isValidBST(self, root: Optional[TreeNode]) -> bool:
        return self.dfs(root, float('-inf'), float('inf'))

    def dfs(self, node, lo, hi):
        if not node:
            return True
        if not lo<node.val<hi:
            return False
        return self.dfs(node=node.left,lo=lo,hi=node.val) and self.dfs(node=node.right,lo=node.val,hi=hi)
```

两个可打磨的小点（不影响正确性）：

1. `not lo<node.val<hi` 靠 `not` 优先级低于比较才等价于 `not (lo<val<hi)`，结果对但加显式括号更醒目
2. 私有 helper 惯例用位置参数，`node=node.left, lo=lo` 这类关键字写法偏啰嗦

### 参考解：中序递增版

```python
class Solution:
    def isValidBST(self, root: Optional[TreeNode]) -> bool:
        self.prev = None
        return self.inorder(root)

    def inorder(self, node):
        if not node:
            return True
        if not self.inorder(node.left):
            return False
        if self.prev is not None and node.val <= self.prev:
            return False
        self.prev = node.val
        return self.inorder(node.right)
```

中序访问序列严格递增 ⇔ 合法 BST。`self.prev` 只存前一个访问值，`is not None` 哨兵处理"还没访问过任何节点"的首元素。

### 手动推演

用 v1 骗过的反例 `[5,4,6,null,null,3,7]`：

```text
    5
   / \
  4   6
     / \
    3   7
```

| 调用 | node | 区间 (lo, hi) | lo < val < hi？ | 结果 |
|------|------|--------------|----------------|------|
| dfs | 5 | (-inf, +inf) | ✓ | 递归左右 |
| dfs | 4 | (-inf, 5) | ✓ | 叶子，True |
| dfs | 6 | (5, +inf) | ✓ | 递归左右 |
| dfs | 3 | **(5, 6)** | 5 < 3 ✗ | **False** |
| dfs | 7 | (6, +inf) | — | （and 短路，实际不执行） |

关键行：3 的区间是 **(5, 6)**——下界 5 从祖父一路传下来，正是 v1"只查父子"漏掉的约束。

## 复杂度分析

| 方法 | 时间 | 空间 |
|------|------|------|
| 区间递归 | O(n) | O(h)，最坏 O(n)（链状树） |
| 中序递归 | O(n) | O(h) |

每个节点最多访问一次（`and` 短路还会更早停）。校验必须检查每个节点，已是最优。

## 错误记录

### 初始错误代码（v1：覆盖 + 只查父子）

```python
ans = True
if not root:
    return ans
if (root.right and root.right.val < root.val) or (root.left and root.left.val > root.val):
    ans = False
ans = self.isValidBST(root=root.left)   # 覆盖
ans = self.isValidBST(root=root.right)  # 再覆盖
return ans
```

### 第二版（v2：结构里外颠倒）

```python
def dfs(self, node, lo, hi):
    if not node:
        if lo>node.val or hi<node.val:   # None 上访问 .val → 崩溃
            return False
        self.dfs(...)                     # 返回值没接住
        self.dfs(...)
        return True
    # 非 None 路径：无 return → 隐式返回 None
```

### 错误分析

| 版本 | 问题 | 说明 |
|------|------|------|
| v1 | ans 连续覆盖 | 本地检查的结果被两次递归赋值冲掉，实际返回"最后一个递归的结果" |
| v1 | 只查父子关系（根因） | BST 约束来自所有祖先；反例 `[5,4,6,null,null,3,7]` 全部父子检查通过，但 3 在 5 的右子树里且 3<5 |
| v2 | 基线分支里外颠倒 | `if not node` 块内访问 `node.val`（None 崩溃），非 None 主路径反而无 return；递归调用只存在于永远进不去的分支里 |
| v2 | 递归结果没接住 | 与 v1 的覆盖同族：子树结果被丢弃 |
| v2 | 边界不严格 | `lo>val or hi<val` 会放过 `val==lo/hi`；BST 要求严格小于/大于 |

### 教训

| 场景 | 做法 |
|------|------|
| BST 校验 | 区间 (lo, hi) 下传：向左收上界、向右收下界；结构固定为"基线 True → 越界 False → and 合并" |
| 递归结果合并 | 用 `and` 链接（自带短路），不覆盖、不丢弃 |
| 入口签名定死还要传状态 | 辅助函数 / 嵌套函数 / self 属性三选一（#543 已用过嵌套函数） |
| 基线分支怎么写 | 基线只处理"参数小到不能再小"的情况并直接返回，主干逻辑写在基线之后 |
| 函数体走完没写 return | 返回 `None`——假值但类型错，judge 判 WA（#94、#108、#98 同一条纪律三连） |

## Python 概念备忘

**隐式返回 None**：函数体走完没有 return 语句 → 返回 `None`，不报错、不返回 False。`None` 是假值，但类型与声明的 `bool` 不符。

**`not` 的优先级低于比较运算符**：`not lo<node.val<hi` 解析为 `not (lo<node.val<hi)`，结果碰巧正确，但显式加括号不依赖读者的优先级记忆。

**无穷边界**：`float('-inf')` / `float('inf')` 当开区间端点；也可用 `None` 哨兵表示"该侧无界"。

**位置参数 vs 关键字参数**：调用函数时两种传参方式，结果一样，纯风格差异。

| 方式 | 写法 | 匹配规则 |
|------|------|---------|
| 位置参数 | `self.dfs(node.left, lo, node.val)` | 按**顺序**：第 1 个实参给第 1 个形参 `node`，第 2 个给 `lo`，第 3 个给 `hi` |
| 关键字参数 | `self.dfs(node=node.left, lo=lo, hi=node.val)` | 按**名字**：每个值标注传给哪个形参，顺序无所谓 |

同一份代码里两种混用（入口是位置、递归是关键字）会显得不统一。三参数、每次全传、顺序固定的私有 helper，惯例直接用位置参数——省掉所有 `名字=` 标签，字数少一半。关键字参数真正有价值的场景：跳过有默认值的中段参数（`plot(x, y, color='red')`）、布尔/数字裸值含义靠位置看不出来（`connect(timeout=30, retry=True)` 比 `connect(30, True)` 可读）、相邻同类型参数防手滑。

## 讨论记录

- v1：指出覆盖 bug 与"只查父子"的根因，用 `[5,10,6]` 演示覆盖（本地抓到 10>5 又被冲掉）、用 `[5,4,6,null,null,3,7]` 引出区间约束洞察。
- 用户追问："力扣函数参数是定死的，这不是自己加参数了吗？"→ 讲透辅助函数模式（类方法 / 嵌套函数 / 带默认值参数 / self 属性四条路），并指出 #543 的 `dfs(node)` 就是同款。
- v2：结构里外颠倒三处修正（基线只 return True、越界检查移出、and 合并）→ AC。
- 沉淀两条等价路线：区间下传（主解）与中序严格递增（参考解）；模板级结论"入口签名定死 ≠ 所有函数签名定死"。
