# 146. LRU Cache

**模式标签**：哈希+链表（LRU 使用序）

**状态**：AC且最优（纠错后通过）

**完成方式**：纠错后通过

- **难度**：Medium
- **标签**：设计、哈希表、链表、双向链表
- **链接**：https://leetcode.cn/problems/lru-cache/

## 题目描述

设计并实现**最近最少使用（LRU）缓存**，要求：

- `LRUCache(int capacity)`：以正整数容量初始化
- `get(key)`：key 存在于缓存则返回其值，否则返回 -1
- `put(key, value)`：key 存在则变更其值；不存在则插入键值对。插入导致容量超过上限时，**逐出最久未使用**的键

`get` 和 `put` 都必须以 **O(1)** 平均时间复杂度运行。

示例（capacity=2）：

```text
输入：["LRUCache","put","put","get","put","get","put","get","get","get"]
     [[2],[1,1],[2,2],[1],[3,3],[2],[4,4],[1],[3],[4]]
输出：[null,null,null,1,null,-1,null,-1,3,4]
```

## 关键思路

核心洞察：⭐ **"使用"包含两种动作——get 命中和 put（插入或更新）**。LRU 要维护的是"访问序"，不是"插入序"。

纯 dict 解法的三根支柱：

1. **dict 保插入序当隐式链表**（Python 3.7+）：头部（`next(iter(d))`）最旧，尾部最新
2. **使用即重插**：每次"使用"（get 命中、put 更新）都 pop 出来再插回尾部——这一下就是手动 move to end
3. **淘汰取头部**：容量满时 `next(iter(cache))` 逐出最久未使用者，O(1)

技巧亲缘：这套"哈希表管查找 + 链表管顺序"的双结构，与 #141/#142 的"哈希表辅助链表"同源；标准实现里双向链表的 dummy 哨兵用法即[链表边界处理笔记](../notes/链表边界处理.md)的哨兵节点套路。

## 代码实现

### 你的 AC 解法（dict 隐式链表版）

```python
class LRUCache:

    def __init__(self, capacity: int):
        self.capacity = capacity
        self.cache = {}

    def get(self, key: int) -> int:
        if key in self.cache:
            self.cache[key] = self.cache.pop(key)   # ⭐ 题眼：命中 = 使用，重插尾部
            return self.cache[key]
        else:
            return -1

    def put(self, key: int, value: int) -> None:
        if key in self.cache:
            self.cache.pop(key)
            self.cache[key] = value
        else:
            if len(self.cache) < self.capacity:
                self.cache[key] = value
            else:
                self.cache.pop(next(iter(self.cache)))   # 逐出头部最旧者
                self.cache[key] = value
```

`get` 里那行 `self.cache[key] = self.cache.pop(key)` 是全题题眼：pop 的返回值就是被"续命"的 value，重插后 key 挪到尾部。put 更新分支的 pop+重插是同一个动作。

两个可打磨的小点（不影响正确性）：

1. `self.capacity=capacity` 等号两侧按 PEP 8 加空格，与标准库风格一致
2. get 里重插后又 `self.cache[key]` 查了一次表——pop 的返回值先存局部变量再返回，可省掉这一次哈希查找：`val = self.cache.pop(key); self.cache[key] = val; return val`

### 参考解 1：OrderedDict 版（官方封装）

```python
from collections import OrderedDict

class LRUCache:
    def __init__(self, capacity: int):
        self.capacity = capacity
        self.cache = OrderedDict()

    def get(self, key: int) -> int:
        if key not in self.cache:
            return -1
        self.cache.move_to_end(key)
        return self.cache[key]

    def put(self, key: int, value: int) -> None:
        if key in self.cache:
            self.cache.move_to_end(key)
        self.cache[key] = value
        if len(self.cache) > self.capacity:
            self.cache.popitem(last=False)
```

`move_to_end(key)` = 你手写的 pop+重插；`popitem(last=False)` = 你手写的 `next(iter())` + pop。纯 dict 版等于手动搓了 OrderedDict 的这两个方法。

### 参考解 2：哈希表 + 双向链表（面试标准答案）

```python
class Node:
    def __init__(self, key=0, val=0):
        self.key = key
        self.val = val
        self.prev = None
        self.next = None

class LRUCache:
    def __init__(self, capacity: int):
        self.capacity = capacity
        self.cache = {}          # key -> Node
        self.head = Node()       # dummy 头：head.next = 最旧
        self.tail = Node()       # dummy 尾：tail.prev = 最新
        self.head.next = self.tail
        self.tail.prev = self.head

    def _remove(self, node):
        node.prev.next = node.next
        node.next.prev = node.prev

    def _push_back(self, node):  # 接到 dummy 尾前（最新侧）
        node.prev = self.tail.prev
        node.next = self.tail
        self.tail.prev.next = node
        self.tail.prev = node

    def get(self, key: int) -> int:
        if key not in self.cache:
            return -1
        node = self.cache[key]
        self._remove(node)
        self._push_back(node)
        return node.val

    def put(self, key: int, value: int) -> None:
        if key in self.cache:
            node = self.cache[key]
            node.val = value
            self._remove(node)
            self._push_back(node)
        else:
            if len(self.cache) == self.capacity:
                lru = self.head.next          # 最旧
                self._remove(lru)
                del self.cache[lru.key]       # ⭐ 靠节点里存的 key 反查删哈希表
            node = Node(key, value)
            self.cache[key] = node
            self._push_back(node)
```

面试要点：

- 哈希表管 O(1) 定位，双向链表管 O(1) 摘除/接尾——缺一不可
- dummy head/tail 两个哨兵让"链表空/只剩一个"的边界分支全部消失（链表边界笔记四件套同款）
- ⭐ 链表节点里必须存 key：逐出时手里只有 Node，要用 `node.key` 反查删哈希表——此题最容易漏的字段

### 手动推演

官方示例，capacity=2，cache 一栏展示 dict 插入序（旧→新）：

| 操作 | cache（旧→新） | 动作 | 返回 |
|------|---------------|------|------|
| put(1,1) | {1:1} | 有空位，直插 | — |
| put(2,2) | {1:1, 2:2} | 有空位，直插 | — |
| get(1) | {2:2, **1:1**} | 1 命中 → pop+重插挪尾 | 1 |
| put(3,3) | {1:1, 3:3} | 满，逐出头 = 2 | — |
| get(2) | {1:1, 3:3} | 未命中 | **-1** |
| put(4,4) | {3:3, 4:4} | 满，逐出头 = 1 | — |
| get(1) | {3:3, 4:4} | 未命中 | -1 |
| get(3) | {4:4, **3:3**} | 3 命中 → 挪尾 | 3 |
| get(4) | {3:3, **4:4**} | 4 命中 → 挪尾 | 4 |

返回序列 1, -1, -1, 3, 4 与期望逐项吻合。第 3 行的挪尾正是 v1 缺失的动作——它不产生返回值差异，却决定了第 5 步谁该被逐出。

## 复杂度分析

| 方法 | 时间 | 空间 |
|------|------|------|
| dict 隐式链表 | get/put 均平均 O(1) | O(capacity) |
| OrderedDict | get/put 均平均 O(1) | O(capacity) |
| 哈希+双向链表 | get/put 均严格 O(1) | O(capacity) |

dict 的 pop、插入、`in`、`next(iter())` 都是平均 O(1)（哈希表特性）；要严格 O(1) 就用双向链表版。缓存条目数不超过 capacity，已是最优。

## 错误记录

### 初始错误代码（v1：get 命中不刷新 recency）

```python
def get(self, key: int) -> int:
    if key in self.cache:
        return self.cache[key]     # ⭐ 缺 move to end
    else:
        return -1
```

（其余部分与 AC 版相同。）

### 错误分析

| 问题 | 说明 |
|------|------|
| get 命中不刷新 recency（根因） | 命中后 key 在 dict 里的位置不动，"最近使用"信息丢失；实现实际是**按插入序淘汰的 FIFO**，不是 LRU |
| 概念偏差：把"使用"只算成 put | LRU 的"使用" = get 命中 + put 插入/更新。put 更新分支已用 pop+重插续命，get 分支漏了同一个动作 |

用官方示例推演 v1：get(1) 后 cache 仍是 {1:1, 2:2}，put(3,3) 逐出 1（正确应逐出 2），随后 get(2) 返回 2、期望 -1 → WA。返不返回值是对的，错在淘汰对象选错。

### 教训

| 场景 | 做法 |
|------|------|
| 实现 LRU | "使用即重插尾部"：get 命中和 put 更新都要 move to end；淘汰固定取头部 |
| dict 当有序结构用 | 它维护的是**插入序**，没有"访问序"；要访问序就手动 pop+重插（或用 OrderedDict.move_to_end） |
| 语义题动手前先对齐定义 | FIFO 和 LRU 只差一句"什么算使用"，代码结构全不同——先问清楚再写 |

## Python 概念备忘

**dict 保插入序（Python 3.7+）**：迭代顺序 = 键首次插入的顺序；对已存在的键赋值**不改变**位置，只有删了重插才挪位。`next(iter(d))` 取首键 O(1)——纯 dict 版淘汰的根基。

**`d[k] = d.pop(k)`（move to end 惯用法）**：pop 取出值并删键，随即重插到尾部。一行完成"取值 + 续命"，等价于 `OrderedDict.move_to_end(k)` 的底层动作。

**OrderedDict**：`collections` 里的有序字典，多出两个 LRU 关键方法——`move_to_end(key)`（挪尾）、`popitem(last=False)`（弹首键）。3.7 后原生 dict 已保序，OrderedDict 的增量价值就在这两个现成方法。

## 讨论记录

- v1：put 三个分支全对（更新重插、有空位直插、满员逐头），但 get 命中不刷新 recency，语义退化成 FIFO；用官方示例手动推演定位到 get(1) 一步信息丢失。
- 用户自行补一行 `self.cache[key]=self.cache.pop(key)` → AC。
- 判定：get/put 均 O(1)，状态"AC且最优（纠错后通过）"。补充面试口径：哈希+双向链表为标准实现，节点必须存 key（逐出时反查删哈希表）。
