# 35. Search Insert Position

**模式标签**：二分查找（lower bound / 插入点）

**状态**：AC且最优（纠错后通过）

**完成方式**：纠错后通过

- **难度**：Easy
- **标签**：数组、二分查找
- **链接**：https://leetcode.cn/problems/search-insert-position/

## 题目描述

给定一个**升序排序**的整数数组 `nums` 和一个目标值 `target`：

- 若 target 在数组中，返回它的下标
- 若不存在，返回它按顺序插入后应处的位置下标

要求算法时间复杂度为 **O(log n)**。假设 nums 中无重复元素。

示例：`nums = [1,3,5,6]`，target=5 → 2；target=2 → 1；target=7 → 4；target=0 → 0。

## 关键思路

先对齐定义：**插入位置 = 第一个 ≥ target 的下标**（target 存在时即它自己的下标；不存在时是第一个比它大的坑位）。这个"一句话定义"决定了后面所有代码形态。

标准迭代二分：

- `lo`、`hi` 两个指针在**原数组**上收缩，循环条件 `while lo <= hi`（闭区间全扫描）
- `target > nums[mid]` → `lo = mid + 1`；`target < nums[mid]` → `hi = mid - 1`；命中即 return
- **循环结束时的 `lo` 就是插入位置**（此时 `lo = hi + 1`，写 hi+1 恒等价）

⭐ 循环不变量（认证地图）：边界每动一步都携带判定证据——

```text
循环中：  [ < target 已验区 | ??? 未验区 | > target 已验区 ]
                ↑lo                ↑mid            ↑hi

循环末：  [ < target 已验区 | > target 已验区 ]
                          ↑ lo = hi+1，未验区缩到空
```

| 动作 | 执行前提 | 顺带认证 |
|------|---------|---------|
| `lo = mid + 1` | 仅当 `nums[mid] < target` | 左侧整段 ≤ nums[mid] < target（有序） |
| `hi = mid - 1` | 仅当 `nums[mid] > target` | 右侧整段 ≥ nums[mid] > target |

所以 `lo` 左边全 `<` target、`hi` 右边全 `>` target，未验区缩空时两段无缝拼合，lo 恰好卡在"第一个 > target"的坑位上。

**等号辨析（早退版 vs lower-bound 版）**：

| 版本 | 命中相等时 | 右侧严格表述 | 返回的 lo 含义 |
|------|-----------|------------|--------------|
| 本题 AC 版（== 早退） | `return mid`，等值元素进不了边界 | 严格 `>` | 第一个 `>` target 的下标（= 插入点） |
| lower-bound 版（不早退） | `hi = mid - 1` 继续收缩，等值被划入右侧 | **`≥`** | 第一个 `≥` target 的下标 = 重复 target 的最左位置 |

`>` 自动满足 `≥`，两版对"无重复、插入点"这个问题答案相同；等号真正落地是在有重复元素、找最左命中时（#34 左边界的引擎）。

## 代码实现

### 你的 AC 解法（迭代二分）

```python
class Solution:
    def searchInsert(self, nums: list[int], target: int) -> int:
        lo = 0
        hi = len(nums) - 1
        while lo <= hi:
            mid = (lo + hi) // 2
            if target > nums[mid]:
                lo = mid + 1
            elif target < nums[mid]:
                hi = mid - 1
            elif target == nums[mid]:
                return mid
        return lo
```

两个可打磨的小点（不影响正确性）：

1. `elif target == nums[mid]` 是前两个分支的补集，写 `else: return mid` 即可
2. 命中分支也可以删掉（命中时走 `hi = mid - 1` 一路收缩到底，统一 `return lo`）——那是 lower-bound 写法，本题用早退版更直白

### 参考解：lower-bound 版（#34 左边界引擎）

```python
class Solution:
    def searchInsert(self, nums: list[int], target: int) -> int:
        lo, hi = 0, len(nums) - 1
        while lo <= hi:
            mid = (lo + hi) // 2
            if nums[mid] < target:
                lo = mid + 1
            else:                     # >= target，等值也划入右侧
                hi = mid - 1
        return lo
```

比 AC 版少一个分支、少一次 return；右侧认证升格为 `≥`，返回"第一个 ≥ target 的下标"。无重复元素时与 AC 版结果完全一致。

### 手动推演

官方四用例，nums=[1,3,5,6]：

| 用例 | 收缩过程 | 返回 | 判定 |
|------|---------|------|------|
| target=5 | mid=1(3)<5→lo=2 → mid=2 命中 | 2 | ✓ |
| target=2 | 3>2→hi=0 → 1<2→lo=1 → 退出 | 1 | ✓ 插入中间 |
| target=7 | lo 一路推到 4 → 退出 | 4 | ✓ 右边界 |
| target=0 | hi 一路退到 -1 → 退出 | 0 | ✓ 左边界 |

右边界、左边界正是 v1 崩掉的两处，迭代版结构性不存在这些问题。

## 复杂度分析

| 方法 | 时间 | 空间 |
|------|------|------|
| 迭代二分 | O(log n) | O(1) |
| v1 切片递归（对照） | O(n)（每层切片拷贝） | O(n)（递归栈 + 新列表） |

n → n/2 → n/4，层数 log₂n，已是最优。

## 错误记录

### 初始错误代码（v1：切片递归版）

```python
class Solution:
    def searchInsert(self, nums: list[int], target: int) -> int:
        mid=nums[len(nums)//2]
        midindex=len(nums)//2

        if target==mid:
            return midindex
        elif target>mid:
            return self.searchInsert(nums[midindex:],target)
        elif target<mid:
            return self.searchInsert(nums[0:midindex],target)
        elif target != mid and len(nums)==1:
            return midindex
```

### 错误分析

| 问题 | 说明 |
|------|------|
| 基线分支位置错误（死代码） | `len(nums)==1` 的返回分支排在所有比较分支之后；只要 target≠mid，`target>mid` / `target<mid` 必然先命中 → 该分支**逻辑上不可达** |
| `nums[0:]` 不缩小规模 → 无限递归 | len==1 时 midindex=0，`nums[0:]` 还是整个数组；target 大于所有元素时层层自调 → RecursionError |
| 切片切出空数组 → IndexError | 左切到 `nums[0:0]=[]`，下一层 `nums[0]` 越界崩溃；基线没兜 len==0 |
| ⭐ 切片导致索引错位（根因） | 返回的是"切片内坐标"，丢了全局偏移；左半边恰好偏移 0 蒙对，右半边必错 |
| 切片 O(n) 拷贝 | 每层拷一半，总代价 O(n)；就算改对，也把二分的时间优势全部吐回去 |

### 三个反例推演

**反例 1：target=7（右边界）→ 无限递归**

| 层 | nums | midindex | mid | 走的分支 |
|----|------|----------|-----|---------|
| 1 | [1,3,5,6] | 2 | 5 | 7>5 → `nums[2:]` |
| 2 | [5,6] | 1 | 6 | 7>6 → `nums[1:]` |
| 3 | [6] | 0 | 6 | 7>6 → `nums[0:]` = 还是 [6] |
| 4 | [6] | … | … | 与第 3 层相同 → **RecursionError** |

**反例 2：target=0（左边界）→ IndexError**

| 层 | nums | mid | 走的分支 |
|----|------|-----|---------|
| 1 | [1,3,5,6] | 5 | 0<5 → `nums[0:2]` |
| 2 | [1,3] | 3 | 0<3 → `nums[0:1]` |
| 3 | [1] | 1 | 0<1 → `nums[0:0]` = **[]** |
| 4 | [] | `nums[0]` → **IndexError** |

**反例 3：target=6 → 索引错位**

| 层 | nums | midindex | mid | 结果 |
|----|------|----------|-----|------|
| 1 | [1,3,5,6] | 2 | 5 | 6>5 → `nums[2:]` |
| 2 | [5,6] | 1 | 6 | 相等 → **return 1** |

全局正确答案 3，返回 1——差了第 1 层切掉的偏移量 2。

### 教训

| 场景 | 做法 |
|------|------|
| 写二分 | 在**原数组**上移动 lo/hi 边界，不动数组本身；切片式二分从根上就是错的 |
| 递归基线 | base case 放在**所有**递归分支之前，否则被前面分支短路成死代码 |
| 切片递归非要写 | 返回值必须拼回偏移（右分支结果 + midindex）；且要兜住空数组 |
| 语义题动手前 | 先写一句话定义（本题："插入位置 = 第一个 ≥ target 的下标"），代码形态跟着定义走 |
| 区间收缩 | `while lo <= hi` 全闭区间扫描，退出时 lo=hi+1 夹逼闭合，lo 即答案 |

## Python 概念备忘

**切片永远新建列表**：`nums[a:b]` 产生新列表，O(b-a)；即使 `a:b` 覆盖全数组（如 `nums[0:]`），拿到的也是**内容相同的副本**，不是原列表——v1 无限递归的技术根源：切了个寂寞，规模一点没小。

**`//` 下取整除**：`mid = (lo + hi) // 2` 取中点偏左；Python 大整数无溢出问题（C/Java 里要用 `lo + (hi-lo)//2` 防溢出，Python 可不管）。
