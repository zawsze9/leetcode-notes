# 437. Path Sum III

**模式标签**：前缀和+哈希（#560 家族变式，双递归暴力为过渡版）

**母题**：#560 Subarray Sum Equals K（转折点见文末；祖父 #1 哈希补数查找）

**状态**：AC非最优

**完成方式**：纠错后通过

- **难度**：Medium
- **标签**：树、深度优先搜索、二叉搜索树
- **链接**：https://leetcode.cn/problems/path-sum-iii/

## 题目描述

统计二叉树中路径和等于 `targetSum` 的路径**条数**。路径不需要从根开始、不需要以叶子结尾，但方向必须**自上而下**（父→子连续）。

示例：`root = [10,5,-3,3,2,null,11,3,-2,null,1]`，`targetSum = 8` → `3`（5→3、5→2→1、-3→11）。

## 关键思路

路径必须竖直（沿父子链），但起点终点都任意。两种拆法：

| 路线 | 思路 | 代价 |
|------|------|------|
| 双递归暴力（你的 AC） | 起点 × 路径：外层每个节点当一次起点，内层数"从该起点向下"的和为 target 的路径 | 最坏 O(n²)，n ≤ 1000 稳过 |
| 前缀和 + 哈希（最优） | #560 移植：根到当前节点的分支和为 cur，哈希表里值为 cur − target 的**祖先前缀**个数 = 以当前节点结尾的路径数 | O(n) |

## 代码实现

### 你的 AC 解法（双递归暴力）

```python
class Solution:
    def pathSum(self, root: Optional[TreeNode], targetSum: int) -> int:
        if not root:
            return 0
        def rootSum(node:Optional[TreeNode],need: int):
            if not node:
                return 0
            return (node.val == need) + rootSum(node.left, need - node.val) + rootSum(node.right, need - node.val)
        return rootSum(root,targetSum)+self.pathSum(root.left,targetSum)+self.pathSum(root.right,targetSum)
```

两个函数拆得很干净：`rootSum` 管"从 node 出发向下"，`pathSum` 枚举每个起点。`(node.val == need)` 以 bool 直接参与加法（`True == 1`），三路相加把子树结果**全部接住**。

### 最优参考：前缀和 + 哈希 + 回溯（O(n)）

```python
class Solution:
    def pathSum(self, root: Optional[TreeNode], targetSum: int) -> int:
        cnt = {0: 1}
        ans = 0
        def dfs(node: Optional[TreeNode], cur: int) -> None:
            nonlocal ans
            if not node:
                return
            cur += node.val
            ans += cnt.get(cur - targetSum, 0)   # 查询在先
            cnt[cur] = cnt.get(cur, 0) + 1        # 插入在后
            dfs(node.left, cur)
            dfs(node.right, cur)
            cnt[cur] -= 1                          # 回溯：出子树撤销自己
        dfs(root, 0)
        return ans
```

三个要点：

1. **`{0: 1}` 空前缀**：处理"从根出发恰好等于 target"的路径（#560 同款）
2. **查询先于插入**：`cur − target` 若恰好等于 `cur`（target = 0），先查后插避免节点匹配自己的零长路径
3. **回溯是树版独有的转折点**：哈希表只允许包含"当前节点到根这条链上的祖先"。不回溯，已访问完的兄弟分支节点的前缀会被误认成祖先，数出物理不存在的路径

### 手动推演

树 `[1, 2, 2]`，`target = 3`（真路径：两条 1→2，答案 2）：

| 调用 | cur（分支和） | 查 cur−target | cnt 变化 | 说明 |
|------|--------------|---------------|----------|------|
| dfs(1) | 1 | cnt[−2] = 0 | `{0:1, 1:1}` | |
| dfs(2 左) | 3 | cnt[0] = **1** → ans=1 | `{0:1, 1:1, 3:1}` → 回溯后 3 移除 | 空前缀命中：路径 1→2 ✓ |
| dfs(2 右) | 3 | cnt[0] = **1** → ans=2 | 同上 | 左子树的前缀已回溯，不干扰 ✓ |

**回溯的必要性**：同一棵树改 `target = 0`（真路径 0 条）。若不回溯，左分支节点留下 `cnt[3]=1`，右分支节点 cur=3 查 `cnt[3]` 命中 → ans=1，凭空多出一条"左孩子到右孩子"的假路径——两者不在一条链上。

## 复杂度分析

| 方法 | 时间 | 空间 |
|------|------|------|
| 双递归暴力 | O(n²) 最坏（链状树：n 个起点 × 每次 O(n)） | O(H) 递归栈 |
| 前缀和 + 哈希 | O(n) | O(n)（哈希表 + 递归栈） |

### 错误分析

| 问题 | 说明 |
|------|------|
| 递归结果没接住 | 两行递归的返回值直接丢弃，返回值最多是 1（#98"覆盖/丢弃"同族）。根源是单函数把"起点枚举"和"路径枚举"搅在一起，正确结构需要两个函数各管一件 |
| 凭感觉怕超时 | O(n²) 想法被自己否决，但 n ≤ 1000 的约束下双层遍历稳过——**怕超时之前先看约束** |

### 教训

| 场景 | 做法 |
|------|------|
| 树上竖直路径和 | 前缀和 + 哈希：查询 cur−target 在先、插入自己在后 |
| 哈希表语义 | 只含当前链上的祖先——回溯撤销，兄弟分支互不可见 |
| 从根出发的路径 | 预置 `{0: 1}` 空前缀（#560 同款） |
| 评估复杂度 | 先看数据范围再决定暴力能不能交 |

## Python 概念备忘

**bool 参与算术**：`True == 1`、`False == 0`，所以 `(node.val == need) + 左 + 右` 是合法的计数写法——匹配到算 1 条。

**回溯的对称性**：进子树前对共享状态 `+1`，出子树后 `-1`，任何"沿途携带、离开即失效"的状态都这样处理。对比 #230 的计数是**单向消耗**（不回溯）——区别在于该状态离开子树后是否还应生效。

## 母题与转折点

**母题**：#560 Subarray Sum Equals K（前缀和+哈希；祖父链：#1 补数查找 → #560 前缀和差值 → #437 树上路径）

**转折点**：① 前缀和定义在"根→当前节点"的**分支**上，换分支必须换状态——哈希表只保留当前链的祖先，引出**回溯**；② 查询先于插入（防 target=0 自匹配）。
