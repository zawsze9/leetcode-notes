# 15. 3Sum

**模式标签**：排序+对撞双指针
**状态**：思路正确但不能AC

- **难度**：Medium
- **标签**：数组、双指针、排序
- **链接**：https://leetcode.cn/problems/3sum/

## 题目描述

找出数组中所有和为 0 的不重复三元组 `[nums[i], nums[j], nums[k]]`，其中 `i != j, i != k, j != k`。

## 关键思路

**排序 + 固定一个数 + 双指针**：将三数之和转化为两数之和问题。

> 先排序，然后固定第一个数 `nums[i]`，问题退化为在 `nums[i+1...n-1]` 中找两个数和为 `-nums[i]`，用对撞双指针 O(n) 求解。排序天然帮助去重 —— 遇到相同的数直接跳过。

## 代码实现

```python
class Solution:
    def threeSum(self, nums: list[int]) -> list[list[int]]:
        nums.sort()
        ans = []
        n = len(nums)

        for i in range(n - 2):
            if nums[i] > 0:
                break
            if i > 0 and nums[i] == nums[i - 1]:
                continue

            left, right = i + 1, n - 1
            while left < right:
                total = nums[i] + nums[left] + nums[right]
                if total < 0:
                    left += 1
                elif total > 0:
                    right -= 1
                else:
                    ans.append([nums[i], nums[left], nums[right]])
                    while left < right and nums[left] == nums[left + 1]:
                        left += 1
                    while left < right and nums[right] == nums[right - 1]:
                        right -= 1
                    left += 1
                    right -= 1

        return ans
```

## 复杂度分析

- 时间复杂度：O(n²)
- 空间复杂度：O(1)（不计输出）

## 错误记录

### 初始错误代码

```python
class Solution:
    def threeSum(self, nums: list[int]) -> list[list[int]]:
        ans = set()
        for ix, x in enumerate(nums):
            seen = {}
            for iy, y in enumerate(nums):
                if iy != ix:
                    target = 0 - x - y
                    if target in seen:
                        ans.add(tuple(sorted((x, y, target))))
                    seen[y] = iy
        return list(map(list, ans))
```

### 错误分析

| 问题 | 说明 |
|------|------|
| **大量冗余遍历** | 内层循环对每个 `ix` 都扫描全部元素，没有利用排序去重，实际上三元组被重复扫描多次 |
| **`tuple(sorted(...))` 开销过大** | 每找到一个三元组都要排序再转元组，在 O(n³) 级别的匹配次数下，频繁创建/排序开销巨大 |
| **set 去重被动** | 靠 set + sorted 去重是"先算出所有、再排重"，不如排序后主动跳过重复元素高效 |
| **常数因子差** | 虽然是 O(n²) 思路，但内层遍历 n 个元素、哈希建表、排序去重，常数因子导致超时 |

### 教训

三数之和类问题优先用 **排序 + 固定 + 对撞双指针**，去重放在循环中主动跳过，避免事后排序去重的昂贵开销。
