# 236. Lowest Common Ancestor of a Binary Tree

**模式标签**：父指针表 + 双链找分叉（后序自底向上为最优参考）

**母题**：#543 Diameter of Binary Tree（最优参考解归属其家族，转折点见文末）

**状态**：AC非最优

**完成方式**：纠错后通过

- **难度**：Medium
- **标签**：树、深度优先搜索
- **链接**：https://leetcode.cn/problems/lowest-common-ancestor-of-a-binary-tree/

## 题目描述

给定二叉树与树上两个节点 p、q，找它们的**最近公共祖先（LCA）**。祖先定义包含自身——若 p 是 q 的祖先，答案就是 p。所有节点值唯一，p、q 必然存在；n 最大 **10⁵**。

## 关键思路

公共祖先恰好构成**从根到 LCA 的一条链**；p 的祖先链与 q 的祖先链的**最后分叉点**就是 LCA。三步：

1. **BFS 建父指针表**（不用递归——n 达 10⁵，链状树递归深度会爆上限）
2. 从 p 沿父指针爬到根，途经节点存入 **set**
3. 从 q 沿父指针往上爬，第一个已在 set 中的节点 = LCA

## 代码实现

### 你的 AC 解法（BFS 建表 + 爬链）

```python
class Solution:
    def lowestCommonAncestor(self, root: 'TreeNode', p: 'TreeNode', q: 'TreeNode') -> 'TreeNode':
        parent={}
        if root:
            queue = deque([root])
            while queue:
                node = queue.popleft()
                if node.left:
                    parent[node.left] = node
                    queue.append(node.left)
                if node.right:
                    parent[node.right] = node
                    queue.append(node.right)
        pparent=set()
        while True:
            pparent.add(p)
            if p==root:
                break
            p=parent[p]
        while True:
            if q in pparent:
                return q
            if q==root:
                break
            q=parent[q]
```

### 最优参考：后序自底向上会合（O(n) / O(H)）

```python
class Solution:
    def lowestCommonAncestor(self, root: 'TreeNode', p: 'TreeNode', q: 'TreeNode') -> 'TreeNode':
        def dfs(node: 'TreeNode') -> 'TreeNode':
            if not node or node is p or node is q:
                return node
            left = dfs(node.left)
            right = dfs(node.right)
            if left and right:
                return node          # 两侧各找到一个 → 会合点即 LCA
            return left or right     # 单侧有发现就往上交
        return dfs(root)
```

返回值语义："这棵子树里找到了 p/q 中的谁（或已确定的 LCA），没有则 None"。自底向上**第一个会合的节点天然最深**，无需记录"最新满足条件的点"。

### 手动推演

```text
        3
       / \
      5   1
     / \ / \
    6  2 0  8
      / \
     7   4
```

p = 5，q = 4（5 恰是 4 的祖先）：

| 调用 | 判定 | 返回 |
|------|------|------|
| dfs(6)、dfs(7) | 非 p/q，无发现 | None |
| dfs(4) | **是 q** → 基线命中 | 4 |
| dfs(2) | 左 None + 右 4 | 4 |
| dfs(5) | **是 p** → 基线命中（q 就在它子树里，停在这里正合适） | 5 |
| dfs(0)、dfs(8)、dfs(1) | 非 p/q，无发现 | None |
| dfs(3) | 左 = 5 有发现，右 = None | **5** ✓ |

`p 是 q 的祖先` 这个边界情况由基线 `node is p or node is q` 自然覆盖——这正是最初构想里预警过的坑。

| BFS 建表 + 爬链（你的） | O(n) | O(n)（父表 + set） |
| 后序自底向上（最优） | O(n) | O(H) |

## 错误记录

### 最初构想（未实现）：逐点祖先检查

前序遍历每个节点，用辅助函数检查"该点是否为 p、q 的公共祖先"，记录最新命中的点。**逻辑正确**（祖先链在前序中按深度递增被访问，最后命中的就是 LCA），但每次检查 O(n)、共 n 个点 → O(n²)，n = 10⁵ 时必超时。

### 错误分析

| 问题 | 说明 |
|------|------|
| 递归建父表 | 链状树递归深度达 10⁵，超 Python 递归上限 → 深树用例 RuntimeError。**约束 10⁵ 时，递归深度本身也是要掂量的资源** |
| `q in pparent` 作用于 list | 线性扫描 O(len)；爬 O(n) 步 × 每步 O(n) → O(n²) |
| `parent[None]` 脏数据 | 孩子为 None 也写入，表里堆垃圾键 |
| 构想阶段凭感觉放弃暴力 | 与 #437 相反方向的一课：约束大时，"能过"的暴力也不存在，必须直接想 O(n) |

## Python 概念备忘

**节点比较用 `is` 不用 `==`**：判断"是不是同一个对象"用身份比较；`==` 落到值比较，节点值可能撞（本题值唯一所以碰巧等价）。dict 的键、set 的成员本来就按对象身份哈希——所以父表和 set 天然是 `is` 语义，无需自定义 `__eq__`。

**BFS 建表模板**：`deque` + 逐节点展开（弹一个、记孩子、入队），是深度不可控时的标准迭代遍历替代品（#102 的层快照管"分层"，这里只要"每个节点被摸一次"，连快照都不需要）。

## 母题与转折点

**母题**：#543 Diameter of Binary Tree（树形后序递归家族——最优参考解归属）

**转折点**：#543 向孩子要"树高"（**数值聚合**，`max` 汇总 + 全局最优）；#236 向孩子要"找到了谁"（**身份聚合**，`left and right` 判会合、`left or right` 上传）。同一个骨架"子信息上汇、父做判断"，聚合的东西不同。你的 AC 解（父指针表 + 爬链）则是独立的模拟式套路，不挂在这个家族下。
