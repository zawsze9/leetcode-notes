# 76. Minimum Window Substring

**模式标签**：变长滑动窗口
**状态**：思路错误

- **难度**：Hard
- **标签**：哈希表、字符串、滑动窗口
- **链接**：https://leetcode.cn/problems/minimum-window-substring/

## 题目描述

找出字符串 `s` 中覆盖 `t` 所有字符的最短子串，包含重复字符的精确数量。

## 关键思路

**变长滑动窗口：先扩充找覆盖，再收缩找最短。**

> 右指针不断右移扩充窗口，直到窗口覆盖 t 的所有字符。此时左指针右移收缩，去掉窗口内多余的字符（在 t 中没出现，或出现次数超了），每收缩一步记录一次最短结果。收缩到窗口不再满足覆盖时，继续右移右指针。

## 代码实现

```python
from collections import defaultdict

class Solution:
    def minWindow(self, s: str, t: str) -> str:
        need = defaultdict(int)
        for c in t:
            need[c] += 1

        need_cnt = len(need)   # 还需满足的字符种类数
        have = 0
        window = defaultdict(int)

        ans = ""
        left = 0

        for right, c in enumerate(s):
            window[c] += 1

            # 恰好凑够该字符的需求量
            if c in need and window[c] == need[c]:
                have += 1

            # 窗口已覆盖 t，尝试收缩左边界
            while have == need_cnt:
                if ans == "" or right - left + 1 < len(ans):
                    ans = s[left:right + 1]

                window[s[left]] -= 1
                if s[left] in need and window[s[left]] < need[s[left]]:
                    have -= 1
                left += 1

        return ans
```

### 手动推演：`s = "ADOBECODEBANC", t = "ABC"`

```
need = {A:1, B:1, C:1}, need_cnt = 3

right 右扩:
  0-A: window{A=1}  A刚好够→have=1
  1-D: ...
  2-O: ...
  3-B: window{B=1}  B刚好够→have=2
  4-E: ...
  5-C: window{C=1}  C刚好够→have=3 ✓ 窗口 "ADOBEC" 已覆盖

left 收缩:
  移出 A → window{A=0}<need{A=1} → have=2  退出收缩

right 继续右扩:
  6-O: ...                         have=2
  ...
  9-B: window{B=2}  already ok    have=2
 10-A: window{A=1}  A刚好够→have=3 ✓ 窗口 "BANC" 已覆盖

left 收缩:
  移出 O,E → 不影响 have
  移出 B → window{B=1}<need{B=1} → have=2  退出收缩

最短: "BANC"
```

## 复杂度分析

- 时间复杂度：O(n)
- 空间复杂度：O(1)（字符集固定）

## 错误记录

### 初始错误思路：两端向内压缩

```python
# 思维路径（错误）
seen = defaultdict(int)
for c in t:
    if c not in s:
        return ""
    else:
        seen[c] += 1

l, r = 0, len(s) - 1
while r - l + 1 >= len(t):
    if s[l] not in t:
        l += 1
    else:
        if seen[l] > 1:   # ← seen[l] 是 int 不是 char
            l += 1
    if s[r] not in t:
        r -= 1
    else:
        if seen[r] > 1:   # ← 同上
            r -= 1
return s[l:r + 1]
```

### 错误分析

| 问题 | 说明 |
|------|------|
| **两端收缩是致命方向错误** | 从两头往中间缩，只能找到"删掉两端垃圾字符后的剩余部分"。但最短子串可能出现在中间位置（如 `"BANC"`），而非包围整个 s 的区间，永远找不到 |
| **`seen` 用途混乱** | 初始化 `seen` 统计了 t 的字符需求，但后续没有用它做需求判断，反而用 `seen[l]`（l 是 int）去比较 >1 —— 逻辑完全断裂 |
| **只删不扩，无法修复** | 从最大窗口开始缩，一旦删过头丢掉必要字符，没有"右指针重新扩张回来"的机制，永远回不去 |
| **无法验证窗口是否覆盖 t** | 缺少"当前窗口是否包含 t 所有字符"的判定逻辑 |

### 图解：为什么两端压缩行不通

```
s = "ADOBECODEBANC", t = "ABC"

两端压缩路线:
  "ADOBECODEBANC"
  → 删左A? 在t中 卡住
  → 删... 无论怎样操作，只会在两端徘徊

正确路线(滑动窗口):
  [A D O B E C]  →  已覆盖, 收缩 →  [A D O B E C] → [D O B E C] → ...
                                        删除左边A后不够了，重新右扩...
  最终找到中间窗: [B A N C]
```

### 教训

| 场景 | 策略 |
|------|------|
| 找覆盖某条件的**最短**子串 | 变长滑动窗口：右扩找覆盖 + 左收缩找最短 |
| 只从两端压缩 | 只能处理"删掉两端无关字符"的简单场景，对子串位置在中间的情况无效 |
| 核心模板 | `while have == need_cnt:` 收缩 + 记录，恢复条件后继续右扩 |
