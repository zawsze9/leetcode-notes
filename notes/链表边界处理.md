# 专题：链表边界处理

> 来源：刷题过程中反复出现的"边界条件改到吐"问题总结
> 涉及题目：#2、#21、#142、#160、#234

## 一、症状清单（你中过哪些）

| 症状 | 例子 |
|------|------|
| 分支爆炸 | #2 先算长度→交换链表→三段循环→每段再塞 if |
| 同一逻辑写多遍 | #2 进位处理写了 3 遍 |
| break 后还要续逻辑 | #2 `if l1.next is None: break` 后外面再补一段 |
| 用长度比较而非判空 | #2 算 m、n 保证 l1 更长；#21 判断 `a.next` 而非 `b is None` |
| 控错变量 | #21 报错在 `b.val`，却去控制 `a == None` |
| 头节点被移动/交换后丢失 | #21 交换后 `return list1` 丢头 |
| 残留调试代码 | #2 `print(l1, l2)` |
| 死代码 | #21 `if a == None: return a` 永远不成立 |

## 二、核心心法

> **不要"先跑主流程，再回头补边界"，而是让边界条件成为主流程的一部分。**

边界不是主流程结束后要额外处理的东西，而是主流程设计之初就应该被循环条件吸收的东西。

## 三、四件套模板

### ① 哨兵节点 dummy

消除头节点特判，统一插入逻辑，最后 `return dummy.next`。

```python
dummy = ListNode()
cur = dummy
# ... 逻辑 ...
return dummy.next
```

**好处**：头节点和中间节点代码一致，不用 `if head is None` 特判；头节点被交换/移动也不怕丢。

### ② 循环条件用 or 承载所有情况

```python
while l1 or l2 or carry:          # 遍历未完或还有进位，都继续
while l1 and l2: ...              # 两个都非空才循环
while fast and fast.next: ...     # 快指针判环防越界
```

**原则**：能写进 while 条件的，绝不写在循环体里 break。`break` 意味着你要在循环外续写逻辑，两段共享状态，必出 bug。

### ③ None 视为 0，判存在而非算长度

```python
v = carry
if l1:
    v += l1.val
    l1 = l1.next
if l2:
    v += l2.val
    l2 = l2.next
```

**原则**：不等长的链表合并/相加，用 `if node:` 判空取值，None 当 0，不要算长度、不要交换链表。

### ④ 进位/余数在循环内消费

```python
cur.next = ListNode(v % 10)
carry = v // 10
cur = cur.next
```

**原则**：状态在循环体内更新并让下一轮自动消费，循环结束即处理完毕，不需要循环外补逻辑。

## 四、对比：同一道题的两种写法

### 写法 A（你的习惯）：分情况 → 崩溃

```
算长度 → 交换 → while l1: 循环到 l2 空 break → 循环外再补 while 处理剩余 → 循环外再补进位
```

### 写法 B（模板）：一循环搞定

```python
dummy = ListNode()
cur = dummy
carry = 0
while l1 or l2 or carry:
    v = carry + (l1.val if l1 else 0) + (l2.val if l2 else 0)
    if l1:
        l1 = l1.next
    if l2:
        l2 = l2.next
    cur.next = ListNode(v % 10)
    carry = v // 10
    cur = cur.next
return dummy.next
```

## 五、调试习惯

1. 提交前 `print` 全删
2. 报错 `NoneType has no attribute 'val'`：先定位**哪个变量**为 None，顺着它的赋值路径找（#21 是 `b = c` 赋出的 None）
3. 头节点被移动过（交换、反转）：用独立变量或哨兵提前记录
4. 小样例手推：`[9,9,9] + [1]`、`[] + []`、单节点、同长/不等长
