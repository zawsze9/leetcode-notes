# 专题：递归

> 来源：#148 归并排序卡壳总结
> 定位：链表/树的递归模板与心智模型

## 一、什么是递归

**函数调用自身，每次调用把问题缩小一点，直到小到可以直接解决。**

```python
def f(n):
    if 终止条件:      # ① base case
        return 直接结果
    return f(缩小后的n)  # ② 调用自身处理更小的问题
```

## 二、递归三要素（写递归先回答三个问题）

| 要素 | 问题 | 例子（#148 切分排序） |
|------|------|----------------------|
| ① 终止条件 | 问题小到什么程度可以直接返回？ | 空链表/单节点 → 直接返回 |
| ② 缩小问题 | 每次调用如何把问题变小？ | 链表切成两半，各排一半 |
| ③ 返回值 | 子调用返回什么？父调用怎么用？ | 返回排好序的链表头，父调用合并 |

**写递归的顺序**：先写 ① 终止条件 → 再写 ③ 用返回值干什么 → 最后补 ② 怎么缩小。

## 三、核心心智模型：信任子调用

> **不要在心里手动模拟递归栈的每一层。** 假设"子调用已经正确完成"，直接把返回值拿来用。

```python
left = self.sortList(head)   # 不要去想它内部怎么排的
right = self.sortList(mid)   # 只要相信: 调用完, left/right 各自有序
# 然后专心做"合并"这一步
```

**这是递归唯一要练习的心态**：只负责"当前这一层 + 子调用的信任"。逐层手推会乱，信任不会。

## 四、为什么递归适合链表/树

链表的递归结构天然匹配：**每个节点都带一个"更小的链表"（next）**。

```
链表: head → (更小的链表)
树:   root → (左子树)(右子树)

父问题 = 当前节点 + 子问题
```

所以链表递归模板：

```python
def solve(head):
    if not head:              # ① 终止
        return base
    sub_result = solve(head.next)   # ② 处理"更小的链表"
    return 组合(head, sub_result)   # ③ 组合当前节点和子结果
```

## 五、链表递归典型例子

### 例 1：合并两个有序链表（#21 递归版）

```python
def mergeTwoLists(l1, l2):
    if not l1:
        return l2
    if not l2:
        return l1
    if l1.val <= l2.val:
        l1.next = mergeTwoLists(l1.next, l2)   # 选小的，剩下的递归
        return l1
    else:
        l2.next = mergeTwoLists(l1, l2.next)
        return l2
```

### 例 2：反转链表（递归版）

```python
def reverseList(head):
    if not head or not head.next:
        return head
    new_head = reverseList(head.next)   # 反转"后面的链表"
    head.next.next = head               # 后面链表的尾指向当前
    head.next = None                    # 当前成为新尾
    return new_head
```

### 例 3：归并排序（#148）

```
sortList(head):
  空/单节点 → 返回 head
  切两半 → 递归排序左右 → 合并（例 1 的逻辑）
```

## 六、和迭代的对比

| 维度 | 递归 | 迭代 |
|------|------|------|
| 思考方式 | 自顶向下（假设子问题已解决） | 自底向上（从小状态堆到结果） |
| 代码 | 短、结构清晰 | 长、要手动管状态 |
| 栈空间 | O(递归深度) | O(1) |
| 适用 | 问题天然分层（树、归并、分治） | 简单线性遍历 |

**选择原则**：问题有"嵌套结构"（树、切半）用递归；纯线性流程用迭代。链表归并排序递归版好写但占 O(log n) 栈空间，迭代版（自底向上）能到 O(1) 空间——见 #148 题解。

## 七、常见错误清单

| 错误 | 后果 | 检查方法 |
|------|------|---------|
| 忘了终止条件 | 无限递归 → 栈溢出 | 先写 base case |
| 问题没有缩小 | 同上 | 参数每次调用必须变小 |
| 返回值没接住 | 结果丢失 | `x = f(...)` 别只写 `f(...)` |
| 终止条件写错位置 | 越界/错解 | 用最小输入手推一层 |
| 手动模拟整个栈 | 思路爆炸 | 信任子调用，只推一层 |

## 八、调试技巧

1. **只推最小层**：用一个 2-3 个元素的小输入，手推第一层和递归返回后的组合
2. **打印深度**：`print("  " * depth, head.val)` 看调用层级
3. **终止条件先测**：空输入、单元素输入是否直接正确返回
4. **画递归树**：树形展开每次调用，检查谁在缩小

3. 心理上：信任子调用，只负责本层组合
